# Invoice production repair

## Root cause

Commit `68087ca8e600c7d53ba6eb2d1a42ced22f51e63a` introduced a useful canonical PDF pipeline, but it also caused two independent production regressions:

1. It deleted the four format-specific React invoice compositions (`A4Template`, `HalfCompactTemplate`, `HalfTopTemplate`, and `ThermalTemplate`) and their shared professional blocks. The replacement renderer reused a reduced generic layout for A4 and Half A4 Compact and substantially compressed Half A4 Top. This removed accounting columns and business/customer detail that were present in parent commit `d5127a8`, and left the Half A4 Top content undersized within its reserved upper half.
2. It replaced the in-app print operation with `open` on macOS and `rundll32 url.dll,FileProtocolHandler` on Windows. Those commands open the default PDF application; they do not open the operating system print dialog. The UI nevertheless described this as native printing.
3. WhatsApp had only a `wa.me` manual deep-link path. That mechanism can prefill text but cannot securely attach and send an arbitrary local PDF, and no authenticated server-side WhatsApp Business Cloud API boundary existed.
4. The release publication job accepted either a Mac or Windows build and rewrote the release manifest with `--replace`. The Mac-only 0.1.8 publication therefore replaced the Windows entries with unavailable values. Publishing now requires verified Mac and Windows x64 installer sets from the same workflow/SHA.

The canonical document work itself is sound and must remain: preview, save, print, WhatsApp, and email must all consume the same cached, validated, nonblank PDF bytes.

## Repair constraints

- Keep SQLite/local-first ERP data authority and existing local databases unchanged.
- Restore a dedicated composition for Full A4, Half A4 Compact, Half A4 Top, and Thermal rather than scaling one generic layout.
- Keep the lower half of Half A4 Top completely blank.
- Preserve the exact footer wording: `Thank you` and `Generated by Bezgrow`.
- Print the already validated canonical PDF with an in-process native system print UI. Do not shell out to Preview, a browser, or the user's default PDF application.
- Treat cancellation as a normal outcome, clear busy state after every attempt, and allow immediate repeat printing.
- Keep automatic WhatsApp delivery optional, explicit, authenticated, and server-side. Never put a WhatsApp Business token in the desktop/web client.
- Preserve manual WhatsApp and email fallbacks and report only actions that actually completed.
- Retain the current hidden Windows server process, readiness gate, and local-first network boundary.

## Verification evidence required

- Structural PDF tests for every format, GST mode, monochrome mode, logo/watermark option, and multi-item fixture.
- Rendered visual checks for A4, both half-page formats, and both thermal widths.
- Contract tests proving macOS uses PDFKit and Windows uses WebView2's system print dialog, with no default-application launcher.
- Tests proving all delivery paths use the canonical PDF document and that automatic WhatsApp delivery is unavailable without server configuration.
- Typecheck, lint, production web build, Rust checks, and desktop/release contract tests before publication.
